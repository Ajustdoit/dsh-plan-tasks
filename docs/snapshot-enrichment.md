# 拆解快照增强：目录树加深 + 模块职责清单

> 解决的问题：模型拆解时**不清楚项目结构**，只能靠目录名猜「该动哪些文件」。

## 一、原快照有多贫乏

改前，拆解时给模型的项目快照只有 **25 行**：

```
- .plan/
- .plan/dispatch.json
- .plan/dispatch.json.bak              ← 噪声
- .plan/dispatch.json.pre-5d           ← 噪声
- .plan/plan.json.bak-1793361457391    ← 噪声
- .plan/plan.json.pre-5d               ← 噪声
- dsh-plan-tasks/
- dsh-plan-tasks/lib/                  ← 到此为止
- dsh-plan-tasks/src/                  ← 到此为止
- dsh-plan-tasks/package.json
```

而实际存在的内容：

| 目录 | 实际 | 模型看到 |
| --- | --- | --- |
| `lib/host/` | **38 个模块** | 只看到「`lib/`」 |
| `src/client/` | 8 个片段 | 只看到「`src/`」 |
| `src/styles/` | 3 个 CSS | 看不到 |
| `docs/` | 18 篇文档 | 看不到 |

**三个问题叠加**：
1. 深度只 2 层 —— 真正要改的文件在**第三层**（`lib/host/api.js`）
2. 噪声文件占位 —— `.bak` / `.pre-*` 挤掉了有效信息
3. 只有文件名没有职责 —— 知道有 `api.js`，不知道它是干嘛的

## 二、改动一：目录树加深 + 过滤噪声

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 深度 | 2 层 | **3 层**（`SNAP_TREE_DEPTH`）|
| 行数上限 | 120 | 200 |
| 噪声文件 | **不过滤** | `.bak` / `.tmp` / `.log` / `.pre-*` / `~` 全部跳过 |

噪声判据（`snapshot.js`）：

```js
const NOISE_FILE = /\.(bak|tmp|log|orig|rej|swp)$|\.bak[-. ]|\.pre[-. ][\w-]*$|\.tmp[-. ]|~$/i
```

效果：同样 200 行预算，能看到的**有效文件**多了一个数量级。

## 三、改动二：模块职责清单（新增段）

从每个源文件的**文件头注释**里抠出一句话，拼成清单：

```
### 模块职责（文件 — 它负责什么）
- dsh-plan-tasks/lib/host/orphan.js — 把「被派发过、但从没真正跑起来」的条目落成已中断
- dsh-plan-tasks/lib/host/api.js — 写型 handler 的统一外壳（id=254）
- dsh-plan-tasks/lib/host/cursor.js — 投递游标（id=342 / id=343）
- dsh-plan-tasks/lib/host/ids.js — 任务编号规则（id=325）
- dsh-plan-tasks/lib/host/store.js — …
```

**这一段排在目录树之前** —— 顺序本身表达优先级：
模型第一眼最需要知道「哪块在管什么」，目录树是细节。

### 提取算法（`dutyOf`）

按**两遍扫描**：

1. **先找块注释** `/** ... */` —— 这是「文件说明」的通行写法
2. 找不到才退回**行注释** `// ...`

必须两遍的原因：单行 `// 某变量说明` 经常出现在文件头，
一遍扫过去会把它误当成文件职责。

扫描时**跳过导入区**（`import` / `export {…} from` / `'use strict'`）——
本仓好几个文件是「import 在前、说明注释在后」，原来碰到 import 就停，
于是一句话都提不出来。

碰到真正的可执行语句（`function` / `const` / `class`）才停下 ——
之后的注释属于函数内部，不是文件说明。

### 覆盖度

| 项 | 结果 |
| --- | --- |
| host 模块提到职责 | **36 / 38** |
| 快照里带职责说明的行 | 48 条 |
| 未提到的 | `http.js`（无文件头注释）、`paths.js`（只有变量注释）|

**未提到的留空，不猜不编** —— 这两处确实是「没有文件级说明」，
硬编一个反而是噪音。

## 四、顺带修掉的一个真 bug

测试时发现：在**受限环境**（沙箱 / 无 git）里，`projectSnapshot` 会**整个崩溃**。

```js
execFile('git', [...], (error, stdout) => { ... })   // 回调只处理「跑起来之后」的失败
```

`execFile` 在 **spawn 阶段**就失败时（EPERM / ENOENT）会**同步抛出**，
回调根本不会被调用 —— Promise 永不 resolve，异常冒泡到 `Promise.all`，
于是**拆解直接失败**。

修法：包一层 `try/catch`，spawn 失败就当「没有 git 历史」。

> 快照是锦上添花的信息源 —— 缺一份 git log 绝不该让拆解挂掉。

## 五、参数变化

| 常量 | 改前 | 改后 |
| --- | --- | --- |
| `SNAP_TREE_MAX` | 120 | 200 |
| `SNAP_TREE_DEPTH` | （硬编码 2）| 3 |
| `SNAP_TOTAL_MAX` | 9000 | 14000 |
| `SNAP_DUTY_MAX` | — | 60（新增）|
| `SNAP_DUTY_LINE_MAX` | — | 96（新增）|

总量从 9000 → 14000，多出约 1.5K token，换来准确的拆分。

| | 改前 | 改后 |

| 快照总长 | ~2.5K 字符（含噪声）| **7.2K 字符** |

## 七、没有加成本

- **不增加模型调用次数**：仍然是一次 `completeOnce`
- **不增加等待时间**：`dutiesOf` 与目录树、README 等**并行**执行
- 读文件只取前 4KB，60 个文件封顶

## 十、已知局限

1. **没有文件头注释的文件提不到职责**（`http.js`、`paths.js`）——
   程序无法区分「文件说明」和「第一个注释」。
   实测 `store.js` 提取到的是「历史遗留的置顶标记键」，属于变量注释而非文件职责。
   **接受这个局限**：36/38 已经足够给模型指路，追求 100% 需要 NLP，不值得。
2. **只扫源码扩展名**（js/mjs/ts/jsx/tsx/py/go/rs/java/css）——
   其他语言的项目拿不到职责清单，但目录树仍然有效。
3. **大项目会被 `SNAP_DUTY_MAX=60` 截断** —— 前 60 个源文件按目录顺序取，
   不保证覆盖最重要的模块。
