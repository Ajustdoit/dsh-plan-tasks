## 1. 一句话概括

它是**「待执行」组头里的一个小胶囊开关**，只在**该组有任务正在执行时**才出现；
绑定单个布尔状态 `pauseAfterDone`；样式全在 `src/styles/` 里（无内联样式），
配色跟随组强调色 `--plt-accent`，状态靠一个小圆点亮/灭表示。

## 2. 渲染位置与所属组件

| 项 | 值 |
| --- | --- |
| 文件 | `src/client/60-tab.js` |
| 行号 | **2093–2115**（`h('button', {…})` 到 `)` 收尾） |
| 所属组件 | 侧边栏主面板里的**分组渲染**（`60-tab.js` 内部的 groups 渲染块） |
| 位置 | **「待执行」(`group.key === 'todo'`) 组头内，紧跟组名之后**（不是最右端） |
| 兄弟元素 | 左：`.plt-caret`（展开箭头）、`.plt-group-name`（组名）<br>右：条数统计（`.plt-group-count`，压在最右端对齐） |

### 显隐条件（三重合取）

```js
group.key === 'todo' && isRunning ? h('button', …) : null
```

1. `group.key === 'todo'` —— 只在**待执行**组；
2. `isRunning` —— 该组**此刻确实有任务在跑**；
   （与组容器上的 `data-running`、收起态那句「正在执行」同一口径）

**无执行中任务 → 整块不渲染**（不是隐藏，是不进 DOM）。

### 为什么在组名右侧而不是最右端

`id=337` 刻意把条数统计压在所有控件之后，让各组数字竖着对齐。
往最右端插一个宽度会变的开关会打散那条对齐线。放在组名右侧，
读起来是「干活中 · 完成后暂停」一句话。

## 3. 绑定的状态字段

| 名称 | 类型 | 位置 | 作用 |
| --- | --- | --- | --- |
| `pauseAfterDone` | `useState(false)` | `60-tab.js:200` | **UI 显示**用（决定文案与 `.on` 类） |
| `pauseAfterDoneRef` | `useRef(false)` | `60-tab.js:186` | **派发回调实际读的值** |

### 为什么有两个

派发逻辑在 `setTimeout` / effect 回调里跑，闭包捕获的是**那一次渲染的** `pauseAfterDone`。
同步写 ref 才能保证「刚拨完开关、同一个事件循环里立刻派发」时读到新值。

**两者必须同步更新**，否则会出现「state 变了、ref 没变」——下一条永远派不出去
（闸门 `60-tab.js:1188` 读的是 ref）。`id=379` 记的就是这个坑。

### 相关常量

| 常量 | 值 | 位置 |
| --- | --- | --- |
| `PAUSE_RESET_IDLE_MS` | **2500** | `00-loader-head.js:110` |
| `NOTICE_LONG_MS` | **5200** | `00-loader-head.js:68` |
| `DISPATCH_SETTLE_MS` | **1200** | `00-loader-head.js:86`（必须小于上面那个） |

## 4. 交互行为

### 文案

| 状态 | 文案 | 含义 |
| --- | --- | --- |
| 关（默认） | **完成后暂停** | 说的是「接下来要做什么」 |
| 开（`.on`） | **继续执行** | 说的是「接下来会怎样」 |

开启后不再重复「暂停」这个动作词 —— 开关已经拨过去了，重复没有信息量。

### 点击（`togglePauseAfterDone`，`60-tab.js:1321`）

```js
onClick: (e) => { e.stopPropagation(); togglePauseAfterDone() }
```

`stopPropagation` 是必须的：组头整行是展开/收起的热区，开关要自己吃掉点击。

拨到**开**：不中断当前任务，只在这一轮结束后不派下一条 + 提示
「当前任务完成后将暂停，不再自动派发下一条」。

拨到**关**：若此时**空闲**（无执行中）且**仍有待执行**，立刻恢复派发；
若**有任务在跑**则不动 —— 它跑完后那个 running 边沿会自然派下一条，
现在多发一次反而会插队。

### 自动复位（`60-tab.js:495` 起，`id=378`）

进入空闲后**延时 2500ms** 复位 `pauseAfterDone = false`。

三个设计点：

1. **为什么复位成 false**：它是「针对当前这一轮」的临时决定，不是长期偏好。
   任务跑完、回到空闲，那次决定的对象已不存在。留着 true 的话，下次开工
   会在用户毫无察觉时停在第一条之后 —— 症状是「点了开始，只跑一条就不动了」，
   且极难联想到是上次那个开关没复位。
2. **为什么要边沿判断**：空闲期间每次 sync 都会重算，不加边沿会在空闲时反复写 state。
3. **为什么要 2500ms 宽限**：会话的 running 在**工具调用之间**会短暂变 false。
   一看到空闲就复位，一条跑十几步工具的任务会在第二个工具调用处被悄悄清掉。

> `PAUSE_RESET_IDLE_MS(2500) > DISPATCH_SETTLE_MS(1200)` 的顺序是**承重的**，
> 别调反。

## 6. 与顶栏「自动刷新」的关系

代码注释明确：小圆点这套视觉语言是**借用**顶栏那颗「自动刷新」（`.plt-auto .plt-dot`）的
—— 亮起 = 开、灰点 = 关，**不新造一个 toggle 皮肤**。

所以改样式时要连带看一眼 `.plt-auto .plt-dot`（**`01-base.css:174`**），
避免两边语义相同却长得不一样。
